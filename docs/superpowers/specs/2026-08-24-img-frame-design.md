# img-frame 设计方案

**日期：** 2026-08-24  
**状态：** 待用户审阅  
**目标：** 构建一个 Windows 桌面应用，读取照片参数并在不覆盖原图的前提下生成带参数相框的无损 PNG。

## 1. 已确认需求

### 1.1 产品形态

- Windows 桌面应用。
- 使用 PySide6 构建界面。
- 所有开发、测试和构建命令使用 `img-frame` conda 环境。
- 首阶段不生成 PyInstaller 应用目录和 Inno Setup 安装包。

### 1.2 输入和输出

- 首阶段支持 JPEG/JPG、PNG 和常见 RAW。
- 首阶段使用 `img-test/` 中的两张 JPG 做真实验收。
- PNG、16-bit PNG 和 RAW 的真实文件测试在补充素材后加入。
- 所有成品统一输出为 PNG。
- 普通 8-bit 源图输出 8-bit PNG。
- 16-bit PNG 和 RAW 输出 16-bit PNG。
- RAW 使用相机白平衡，不自动提亮，转换为 16-bit sRGB。
- 输出保留 ICC 色彩配置文件。
- 输出不写入 EXIF、XMP、IPTC、GPS、厂商私有字段或 PNG 文本块。
- 原图区域在完成方向校正后保持逐像素一致；相框在原图外部扩展，不覆盖原图。

### 1.3 显示内容

默认相框只显示两行，整体水平居中：

```text
相机型号
焦距    快门速度    光圈    ISO
```

实际绘制只显示值，不显示参数名称，例如：

```text
NIKON D750
50mm    1/250s    f/2.8    100
```

- 不显示镜头信息。
- 相机型号缺失时隐藏第一行。
- 其他字段缺失且未手动填写时隐藏该字段，剩余字段重新排列并保持居中。
- 用户可以手动填写或修改所有显示字段。
- 字体统一使用微软雅黑。

### 1.4 相框默认值和可配置项

- 默认材质：纯白。
- 默认结构：经典外扩。
- 默认文字颜色：根据背景亮度自动选择黑色或白色。
- 默认文字和相框内容整体水平居中。
- 可配置颜色、透明度、边框厚度、字号和磨砂效果。
- 磨砂效果使用照片边缘延展后高斯模糊，再叠加颜色层。
- 普通颜色模式的透明度控制相框 Alpha。
- 磨砂模式的透明度控制颜色覆盖强度。
- 边框厚度、字号和模糊半径按原图短边百分比保存，并显示像素换算。

### 1.5 文件和交互

- 支持单张图片处理。
- 支持实时预览、缩放和适应窗口。
- 支持自定义输出目录。
- 默认输出目录为源图片所在目录。
- 用户选择过的输出目录使用 QSettings 记住。
- 输出文件默认使用 `_framed.png` 后缀。
- 文件冲突时自动递增为 `_framed_1.png`、`_framed_2.png` 等。
- 永不覆盖原图或已有成品。

## 2. 设计决策

### 2.1 图像处理架构

采用 Pillow + NumPy 双路径：

- Pillow 负责 JPEG、8-bit PNG 的读取、合成和 PNG 写出。
- NumPy 负责 16-bit PNG、RAW 解码后的高位深像素合成和导出。
- Pillow 负责字体栅格化和文字蒙版生成。
- rawpy/LibRaw 负责 RAW 解码、相机白平衡和 16-bit sRGB 输出。
- ExifRead 优先读取常用 EXIF 字段。
- ExifTool 用于 RAW、厂商私有字段和 ExifRead 无法读取的字段。

预览和导出使用同一套纯图像核心，但输入源不同：

- 预览先生成屏幕尺寸的缩放副本，以保证交互流畅。
- 导出始终从完整分辨率源像素重新渲染。
- 预览缩放副本绝不作为导出来源。

### 2.2 相框结构

采用“经典外扩”：

- 顶部和左右侧生成等宽外扩边框。
- 底部在相同边框基础上增加两行文字信息区。
- 输出画布尺寸为原图尺寸加外扩边框和底部信息区。
- 原图像素直接复制到输出画布对应区域，不进行二次缩放。

### 2.3 位深和色彩

- 读取阶段记录源位深和 ICC。
- 8-bit 源图保持 8-bit 输出。
- 16-bit PNG 和 RAW 保持 16-bit 输出。
- RAW 转换到 sRGB，并嵌入标准 sRGB ICC。
- 除 ICC 外不迁移任何元数据。
- 输出通过临时文件写入，成功后再移动为唯一目标名称。

## 4. 数据流

```text
选择图片
  ↓
识别 JPEG/PNG/RAW
  ↓
读取完整源像素、位深、方向和 ICC
  ↓
读取相机型号、焦距、快门、光圈、ISO
  ↓
创建 ImageSession
  ↓
用户编辑参数或相框配置
  ↓
150 ms 短延迟合并后刷新预览
  ↓
用户选择输出目录并导出
  ↓
从完整源像素计算经典外扩画布
  ↓
生成相框背景和两行居中文字
  ↓
按源位深写出 PNG，只附加 ICC
  ↓
完成后生成唯一文件名并显示路径
```

`ImageSession` 至少包含：

- 源文件路径和格式。
- 完整分辨率源像素。
- 源位深。
- ICC 色彩配置。
- 方向校正后的显示基准。
- 读取到的原始元数据快照。
- 用户当前编辑后的显示参数。
- 当前 `FrameConfig`。

用户编辑值只影响相框文字，不修改源元数据，因为最终 PNG 明确不写入元数据。

## 5. 界面设计

主窗口采用已批准的方案 A：中央大预览、左侧快捷工具、右侧参数和相框面板、底部输出栏。

### 5.1 顶部标题栏

- 应用名称 `img-frame`。
- 当前文件名、原图尺寸和位深。
- 使用系统窗口控制按钮。

### 5.2 左侧快捷工具

- 打开图片。
- 适应窗口。
- 实际大小。
- 放大。
- 缩小。

### 5.3 中央预览

- 显示完整相框效果。
- 相框文字实时水平居中。
- 显示当前缩放比例。
- 支持适应窗口和实际大小。
- 加载和导出时显示忙碌状态。

### 5.4 右侧照片参数

控件标签可以显示字段名称，但成品相框不显示字段名称：

- 相机型号。
- 焦距。
- 快门速度。
- 光圈。
- ISO。
- `恢复读取值` 操作，撤销用户编辑并恢复 EXIF 读取值。

### 5.5 右侧相框设置

- 纯色/磨砂分段控件。
- 颜色选择器和预设色板。
- 透明度滑块。
- 边框厚度滑块。
- 文字大小滑块。
- 磨砂模式下启用模糊半径滑块。
- `恢复默认` 操作。

### 5.6 底部输出栏

- 当前输出目录。
- 选择输出目录按钮。
- 输出文件名预览。
- 导出 PNG 按钮。

默认输出目录为源图片所在目录，用户选择的新目录通过 QSettings 记住。

## 6. 排版和渲染规则

### 6.1 文本内容

相机型号存在时绘制第一行。第二行依次尝试绘制焦距、快门、光圈和 ISO，仅加入非空值。

示例：

```text
Canon EOS R5
50mm    1/250s    f/2.8    100
```

如果所有第二行字段都为空，则只绘制相机型号；如果相机型号也为空，则不绘制文字区域。

### 6.2 字体和字号

- 字体家族固定为微软雅黑。
- 相机型号字号大于参数行。
- 用户字号按原图短边百分比设置。
- 文本过长时逐步缩小，最小为用户设置值的 60%。
- 最小字号仍无法容纳时，按完整文本绘制，不裁切，不换成参数名称。

### 6.3 颜色

- 背景亮度较高时使用黑色文字。
- 背景亮度较低时使用白色文字。
- 文字不额外描边，避免破坏纯净相框风格。

### 6.4 磨砂

1. 从原图边缘生成外扩采样区域。
2. 对采样区域执行高斯模糊。
3. 按透明度叠加用户选择颜色。
4. 在最终背景上绘制两行文字。

磨砂背景只作用于外扩相框，不改变原图区域。

## 7. 错误处理

应用不因单张图片失败而退出，错误转换为中文、可操作提示。

| 场景 | 处理方式 |
|---|---|
| 未选择文件 | 显示打开图片入口，禁用设置和导出 |
| 不支持格式 | 提示支持 JPEG/JPG、PNG 和 RAW，保留当前图片 |
| 文件损坏 | 显示路径和原因，允许重新打开 |
| RAW 解码失败 | 提示解码失败，不生成低质量替代图 |
| EXIF 缺失 | 字段留空，允许手动填写 |
| 参数格式非法 | 输入框标红，禁用导出并说明格式 |
| 输出目录不可写 | 提示选择其他目录 |
| 文件名冲突 | 自动生成递增名称 |
| 内存不足 | 提示降低系统负载或处理较小图片 |
| ExifTool 不可用 | 常规图片继续处理，缺失字段提示组件状态 |
| 导出中重复点击 | 按钮进入忙碌状态，禁止重复提交 |
| 导出失败 | 删除临时文件，保留原图和已有成品 |

成功后显示目标路径，并提供打开输出目录的操作。

## 8. 测试策略

### 8.1 单元测试

覆盖不依赖界面的纯逻辑：

- EXIF 字段标准化。
- 快门、光圈、焦距和 ISO 格式化。
- 缺失字段隐藏和自动重新排列。
- 两行文字居中布局。
- 长文本自动缩小。
- 经典外扩画布尺寸计算。
- 8-bit 和 16-bit 位深分支。
- 黑白文字自动选择。
- 自动文件名递增。
- 输出路径不覆盖原图。

### 8.2 图像处理测试

首阶段使用 `img-test/DSC_0061.JPG` 和 `img-test/DSC_0050.JPG`：

- 两张 JPG 都能成功读取。
- 可以读取已有相机参数，读取不到的字段可以手动填写。
- 输出 PNG 可以重新打开。
- 输出 PNG 只保留 ICC，不包含 EXIF、XMP、IPTC、GPS 和文本元数据。
- 方向校正后的原图区域逐像素一致。
- 输出尺寸等于原图尺寸加相框外扩尺寸。
- 白色、黑色和磨砂模式均能导出。
- 修改透明度、厚度和字号后输出符合配置。
- 原图不会被覆盖。

PNG、16-bit PNG 和 RAW 的真实文件测试在补充素材后加入测试夹具。

### 8.3 界面测试

- 空状态可以打开图片。
- 加载期间界面不冻结。
- 参数编辑刷新预览。
- 纯色/磨砂切换正确启用或禁用控件。
- 输出目录选择生效并被记住。
- 导出中不能重复点击。
- 成功后可以打开输出目录。
- 错误提示不会清空当前有效会话。

### 8.4 手动验收

1. 打开现有两张 JPG。
2. 修改相机型号、焦距、快门、光圈和 ISO。
3. 切换三种相框材质。
4. 调整透明度、边框厚度和字号。
5. 检查两行文字始终水平居中。
6. 导出并检查 PNG 可正常打开。
7. 检查元数据仅保留 ICC。
8. 重复导出并确认不会覆盖已有文件。
9. 重启应用并确认输出目录设置保留。

## 9. 首阶段运行方式

首阶段只在 `img-frame` conda 环境中运行和验证桌面应用：

```text
conda activate img-frame
python -m app.main
```

首阶段不执行 PyInstaller，也不调用 `D:\Inno Setup 6`。ExifTool 作为项目运行时依赖放在项目目录内，或由开发环境提供可执行文件路径。

## 10. 首个版本验收标准

首个可交付版本必须满足：

1. 在 `img-frame` conda 环境中可以启动 Windows 桌面应用。
2. 现有两张 JPG 可以完整处理。
3. 输出统一为 PNG，并保留 ICC。
4. 除 ICC 外不写入元数据。
5. 原图区域不被相框覆盖。
6. 源位深策略在代码路径中落实。
7. 默认白色、经典外扩、文字居中。
8. 相框两行布局符合已确认规则。
9. 不覆盖原图。
10. 主要失败场景都有中文提示。
11. 自动化测试通过。
